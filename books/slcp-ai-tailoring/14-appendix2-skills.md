本別添では、第6章の前提スキルと第7章の目指すスキルを、表の形で並べる。読み方は段階である。標準となる知識（IPAのシラバス）を土台とし、その上に前提スキルが乗り、さらにその上に、判断と振る舞いの層である目指すスキルが載る。

### 表1 前提スキルとシラバスの対応（第6章）

| 前提スキル      | 内容                             | 対応するシラバスの項目                                                  |
| ---------- | ------------------------------ | ------------------------------------------------------------ |
| プロセスの読み解き  | 各プロセスの入力と成果物を読み、自分の仕事の位置を見渡す   | 開発技術「開発プロセス・手法」（共通フレーム、JIS X 0160、JIS X 0170、プロセス修整（テーラリング）） |
| ドメイン理解     | 対象業務の流れと用語と勘所を掴む（本稿の事例では商・物流）  | ビジネスインダストリ「ビジネスシステム」（流通情報システム、物流情報システム、SCM、トレーサビリティ）         |
| 仕様・図での検証能力 | 仕様書と設計の図を読み、生成物の一致を確かめる        | システム開発技術（要件定義、設計、統合テスト）                                      |
| 根拠を要求する姿勢  | 成果物と説明に根拠を求め、根拠のないものを確定として扱わない | システム監査。計測の側では目標・評価（KGI・KPI）と経済性計算（ROI）                       |

### 表2 業務側の層（第6章）

業務側のAIリテラシーは、シラバスの項目としてではなく、前提として置く。

| 力             | 役割                   |
| ------------- | -------------------- |
| 目的を言葉にする力     | 課題意識を、様式化できる形で開発側へ渡す |
| AIの出力を吟味する力   | 業務の側で、出力の当否を確かめる     |
| 機密と公開の線引きを引く力 | AIに渡してよい情報の範囲を定める    |

### 表3 目指すスキル（第7章）

目指すスキルは知識の項目の形には表れない。判断と振る舞いの層として、表1の前提スキルの上に載る。

| 目指すスキル        | 内容                                      | 主に担う場所        |
| ------------- | --------------------------------------- | ------------- |
| 目的を明確にする      | 何のために作るのか、誰の何を変えるのかを言葉にして保持する           | 超上流、要件定義の判断   |
| 思考を明確にする      | 判断の根拠と前提を言葉にし、意味と単位と命名を保持し、例外を判断する      | 設計の判断、ゲートでの判断 |
| 手段は材料で支える     | 制約と根拠を材料として用意し、実行はAIに委ね、生成物を材料に照らして検証する | 設計以降の分担       |
| レビューゲートでの盲点検出 | 生成側の盲点を、目的と設計の図を物差しとして検出する              | レビューゲート       |

なお、表1の引くシラバスは応用情報技術者試験のものである。2027年度からの新制度（プロフェッショナルデジタルスキル試験（仮称））では、共通知識の中分類「システムライフサイクルプロセス」がこの土台を引き継ぐ（第6章）。

参照元: 独立行政法人情報処理推進機構（IPA）「応用情報技術者試験シラバス Ver.7.2」。新制度の試験区分と共通知識の構成は、IPAが公表した新制度のシラバス案による。
